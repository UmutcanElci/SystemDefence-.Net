# SystemDefence-.Net

First of all, this is primarily a personal note to myself, but also a brief explanation for anyone who happens to stumble upon this repository and finds it interesting.

I initially started this project as a preparation and showcase for a specific job interview. However, since the application process didn't conclude the way I wanted, I no longer have a compelling reason to actively continue developing it. My main goal here was to refresh my memory and dive deeper into the .NET ecosystem, asynchronous database operations, N-Tier architecture, and string manipulations. In that regard, it completely served its learning purpose for me.

Calling this project "half-finished" or "abandoned" would be a bit unfair to it. It is more accurate to say that only about 20% of it is complete. **However**, I strongly believe that the project's core structure is still very open to adding new features, making it a great playground for learning and self-improvement.

There are, of course, many shortcomings and missing pieces in its current state. For instance, the database needs to pull a much wider and more interesting variety of data to make the scenarios engaging. Right now, the missions are quite basic; everything feels like it's stuck at a "Level 2" difficulty, which makes the text and overall structure a bit repetitive and dull. The terminal visuals and colors are also too fundamental. Integrating a modern terminal library would make the interface look much more appealing and modern.

I did write some tests, but they are a bit biased. They all pass right now, but I am absolutely sure there are edge cases I missed, meaning the functions inside the tools definitely need a thorough review. As for the gameplay itself, it's almost non-existent and way too simple. It needs to be developed in a way that actually forces the player to sit down, think, and solve real problems.

There are definitely many more bugs and flaws hidden inside, but the potential is there to build something simple yet effective for learning. For example, I only added `StringArsenal` because it served my immediate string manipulation needs, but the architecture allows for much more. Someone could easily add a `NumberArsenal`, or introduce entirely new tools based on search and sorting algorithms to create a much deeper logical structure. Furthermore, the missions shouldn't have one-dimensional solutions; the system could be expanded so that solving a single problem requires using multiple different tools piece by piece.

There is a lot more that could be said, but as I mentioned, I just wanted to leave this note explaining what I wanted to do, why I left it at this stage, and the potential it holds for anyone (including myself in the future) wanting to tinker with it.
